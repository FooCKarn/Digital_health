# docs/extraction-pipeline.md: ดึงข้อมูลจากหนังสือ TTM first

เป้าหมาย: แปลง PDF (206 หน้า, สมุนไพรเดี่ยว 50 ชนิด) เป็น `data/herbs.json` ที่ **วัดความแม่นยำได้** และทุกฟิลด์ความปลอดภัยผ่านการตรวจโดยคน

## 0. ข้อสังเกตจากการสำรวจเบื้องต้น (บันทึกไว้เพื่อไม่ต้องทำซ้ำ)

- ไฟล์มี text layer (ฟอนต์ฝัง Sarabun/PTT45Pride) ไม่ต้อง OCR; `pdftotext -layout` ใช้ได้
- ข้อความมีสระ/วรรณยุกต์ซ้ำ (เช่น "ส้้ม", "ทำำ") และอักขระแปลก (U+FFFD) ในบางจุด และเว้นวรรคกลางคำ
- การแยกหน้า: ผลลัพธ์ `pdftotext` คั่นหน้าด้วย `\f`; 2 หน้าแรกอาจว่าง
- เลขหน้าที่พิมพ์ (printed) กับหน้าในไฟล์ (PDF page) ต่างกัน: จากรายการขิง หน้า PDF ที่ 87 = หน้าพิมพ์ 79 (ต่างกัน 8) **ใช้เป็นแนวทางเริ่มต้น ต้องตรวจซ้ำกับหลายช่วงหน้า** เพราะส่วนต้นเล่มใช้เลขโรมัน และอาจมีหน้าแทรก
- ส่วนรายการสมุนไพรเริ่มราว หน้าพิมพ์ 34 (หลังส่วนอาการ) แต่ละชนิดใช้แม่แบบเดียวกัน
- รสอยู่ในรูปข้อความอิสระรายส่วนของพืช ("เหง้ามีรสหวานเผ็ดร้อน มีสรรพคุณ...")
- กระวาน (ลำดับ 4) ตัวแยกรสอัตโนมัติจับไม่ได้ ต้องดูมือ
- เลขลำดับ/ชื่อที่ regex จับได้ครบ 50 รายการ แต่บางชื่อมีอักขระซ้ำ (เช่น "กล้วยน้ำำว้า้") ต้อง normalize

## 1. แม่แบบของแต่ละรายการสมุนไพร

หัวข้อตามลำดับ: 1) ชื่อวิทยาศาสตร์ ชื่อพ้อง ชื่อวงศ์ ชื่อสามัญ ชื่อท้องถิ่น 2) ส่วนที่ใช้ รสและสรรพคุณยาไทย 3) วิธีใช้ (แยกตามอาการ พร้อมขนาด) 4) ข้อห้ามใช้ / คำเตือน / ข้อควรระวัง (อาจอยู่ก่อนหรือหลังหัวข้อลักษณะพืช) 5) ลักษณะพืช 6) การขยายพันธุ์ 7) ข้อมูลการใช้เป็นอาหารและคุณค่าทางโภชนาการ 8) องค์ประกอบทางเคมี 9) ข้อมูลวิจัย 10) เอกสารอ้างอิง

**ฟิลด์ที่ต้องสกัด (ความปลอดภัย):** ข้อห้ามใช้, คำเตือน, ข้อควรระวัง, ขนาดและระยะเวลา, สรรพคุณ/อาการ (สำหรับ R6) ฟิลด์อื่น (ลักษณะพืช เคมี งานวิจัย) ไม่จำเป็นสำหรับ MVP

## 2. ขั้นตอน

### ขั้น 1: ทำความสะอาดข้อความ (`scripts/extract_pdf.py`)
```
pdftotext -layout input.pdf raw.txt
```
แล้ว normalize:
- ยุบอักษรผสมไทย (สระบน/ล่าง วรรณยุกต์ ฯลฯ ช่วง U+0E31, U+0E34-U+0E3A, U+0E47-U+0E4E) ที่ซ้ำติดกันให้เหลือตัวเดียว
- ลบ U+FFFD และอักขระแปลกที่ไม่ใช่ไทย/ละติน/ตัวเลข/เครื่องหมายทั่วไป
- เก็บ **ข้อความดิบคู่กับข้อความที่ล้างแล้ว** พร้อมเลขหน้า PDF ทุกบรรทัด/ย่อหน้า เพื่อให้ย้อนตรวจได้
- ระวัง: การล้างอาจทำให้ "ำำ" → "ำ" และ "ํา" ผิดรูป ให้ตรวจตัวอย่างหลายคำก่อนใช้จริง

### ขั้น 2: แยกรายการสมุนไพร
กฎที่ใช้ได้ผลในการสำรวจ: หน้าที่ขึ้นต้นด้วย `"<เลข>. <ชื่อ>"` และใน 600 ตัวอักษรแรก (ลบช่องว่างทั้งหมดแล้ว) มี "วิทยาศาสตร์" และ "ชื่อวงศ์" เริ่มค้นหลังหน้าที่ 30 ของไฟล์ ผลคือครบ 50 รายการ (ลำดับ 1 กระเจี๊ยบแดง ถึง 50 สมุนไพรไทย: สมอไทย) บันทึกช่วงหน้า PDF ของแต่ละรายการ

### ขั้น 3: สกัดโครงสร้าง 2 รอบด้วยวิธีต่างกัน
- **รอบ A (กฎ/regex):** ตัดหัวข้อตามคำนำ ("ข้อห้ามใช้", "คำเตือน", "ข้อควรระวัง", "รสและสรรพคุณ", "วิธีใช้") ผลเป็นข้อความต่อหัวข้อ
- **รอบ B (LLM):** ให้ LLM แปลงข้อความต่อหัวข้อเป็น JSON ตาม `docs/data-schema.md` โดยบังคับ: ห้ามเพิ่มข้อมูลนอกข้อความที่ให้ ถ้าไม่พบให้ `null` ต้องคัดลอกวลีต้นทางสั้น ๆ ที่เป็นหลักฐานของแต่ละรายการ (`evidence_quote` เก็บไว้ใช้ตรวจ ไม่นำไปแสดงเป็นข้อความยาวใน UI)
- เก็บผลทั้งสองรอบ แล้ว **เทียบกัน** ที่ระดับฟิลด์

### ขั้น 4: ตรวจหาจุดไม่ตรงกัน (`scripts/verify_extraction.py`)
รายงาน:
- ฟิลด์ที่รอบ A กับ B ไม่ตรงกัน (ตรวจมือก่อน)
- รายการที่ `evidence_quote` ไม่ปรากฏในข้อความต้นทาง (สัญญาณว่า LLM แต่งเพิ่ม → ปัดตก)
- สมุนไพรที่ไม่มีข้อห้าม/คำเตือนเลย (ตรวจว่าเล่มไม่มีจริงหรือสกัดตก) เช่น ฟักทอง มะแว้งเครือ ที่ข้อห้ามใช้เป็น "-"
- ตัวเลข (ขนาด จำนวนวัน อายุ) ที่ต้นทางมีแต่ผลสกัดไม่มี หรือกลับกัน

### ขั้น 5: คนตรวจกับต้นฉบับ
- เปิด PDF ทีละรายการ ตรวจฟิลด์ความปลอดภัย 100% แล้วตั้ง `verified: true`, `verified_by` และบันทึกวันที่
- แก้เลขหน้าให้เป็นหน้าพิมพ์ที่ถูกต้อง (หรือเก็บทั้ง PDF page และ printed page)
- บันทึกข้อผิดพลาดที่พบเพื่อรายงานความแม่นยำ

### ขั้น 6: รายงานความแม่นยำ
เทียบกับ **golden set สกัดมือ** (เลือก 10 รายการ สุ่มให้ครอบคลุม: มีคำเตือนยา, ไม่มีข้อห้าม, รสหลายส่วนพืช, ข้อจำกัดระยะเวลา) รายงาน:
- ความถูกต้องรายฟิลด์ของรอบ A, รอบ B และผลรวมหลังเทียบกัน
- จำนวนข้อผิดพลาดที่ผู้ตรวจพบต่อรายการ และชนิดของข้อผิดพลาด
- เวลาที่ใช้ตรวจต่อรายการ

ตัวเลขนี้คือหลักฐานตอบกรรมการว่า "ข้อมูลน่าเชื่อถือแค่ไหน" ห้ามรายงานตัวเลขที่ไม่ได้วัดจริง

## 3. ลำดับการทำงานที่แนะนำ

1. ทดลองกับ **5 ตัว** (กระเทียม ขิง มะขาม รางจืด ขี้เหล็ก) ทำขั้น 1-5 ครบ แล้ววัดเวลาและความถูกต้อง
2. ตัดสินใจว่าวิธีนี้ใช้ได้กับ 50 ตัวหรือไม่ ถ้าผิดพลาดมากให้ปรับ prompt/กฎก่อนขยาย
3. ขยายเป็น 50 ตัว
4. ทำ golden set สกัดมือ + รายงานความแม่นยำ

## 4. ข้อควรระวัง

- **อย่าเชื่อผลสกัดของ LLM ในฟิลด์ความปลอดภัยโดยไม่ตรวจ** แม้สองรอบตรงกัน ก็ยังต้องมีคนตรวจกับต้นฉบับ (สองวิธีอาจผิดเหมือนกันได้)
- **ความหมายของคำเตือน:** ข้อความอย่าง "ผู้ป่วยที่ได้รับยาต้านการแข็งตัวของเลือด ไม่ควรรับประทาน" กับ "ควรปรึกษาแพทย์ก่อนใช้" มีระดับต่างกัน ต้องรักษาระดับตามต้นฉบับ (`avoid` vs `caution`) และเก็บบริบท เช่น ขิงห้ามใช้บรรเทาคลื่นไส้ในสตรีมีครรภ์ (ไม่ใช่ห้ามทุกกรณี)
- **เนื้อหาข้ามหน้า:** ข้อห้าม/คำเตือนอาจคาบหน้า (เช่น ขิงขึ้นหน้า 79 จบหน้า 80) ต้องเก็บหน้าที่ข้อความจริงอยู่
- **ข้อความระหว่างหน้า:** ส่วนท้ายกระดาษ ("แนวทางการใช้ยาสมุนไพร ... เลขหน้า") ปะปนในข้อความ ต้องกรองออกก่อนสกัด
- **ลิขสิทธิ์:** เก็บข้อความต้นฉบับใน repo ส่วนตัวเพื่อตรวจเท่านั้น อย่าแสดงข้อความยาวใน UI/สไลด์ สรุปความและอ้างหน้า
