# docs/rules-spec.md: สเปกกฎของ Rule Engine

หลักการ: engine เป็นฟังก์ชันล้วน `check(input, data, config) -> result` ไม่เรียก LLM ไม่มี side effect input เดิมต้องได้ output เดิม ทุกกฎคืน flag ตาม schema ใน `docs/data-schema.md` ข้อ 6

## ภาพรวม

| กฎ | ชื่อ | ชั้นหลักฐาน | สถานะใน MVP |
|---|---|---|---|
| R1 | ข้อห้ามตามเงื่อนไขผู้ใช้ (ตั้งครรภ์ อายุ โรค) | A | ต้องมี |
| R2 | สมุนไพร × กลุ่มยา | A, C | ต้องมี |
| R3 | รวมภาระความเสี่ยงตาม mechanism tag | A, C | ต้องมี (จุดต่าง) |
| R4 | ระยะเวลา/ขนาดเกินกำหนด | A | ต้องมี |
| R5 | red flag อาการ (ควรไปพบแพทย์) | A | ทำถ้ามีเวลา (หลัง R1-R4, R6) |
| R6 | Safe-swap: เสนอทางเลือกที่ไม่ติดธง | A (จากเล่ม) | ทำถ้ามีเวลา (ตัดก่อนการทดลองผู้ใช้) |

## Input

```json
{
  "herbs": [{"id": "khing", "part": "เหง้า", "days_in_use": 3, "dose_note": null}],
  "drugs": ["warfarin"],
  "profile": {"age": 60, "pregnant": false, "breastfeeding": false, "conditions": ["liver_disease"]},
  "symptoms": ["dyspepsia"]
}
```
- `herbs[].id` และ `drugs[]` ผ่านขั้นตอน normalize/ยืนยันโดยผู้ใช้แล้ว ถ้าไม่พบในฐาน ให้ใส่ใน `coverage.unknown_inputs` และไม่เดา
- `conditions` ใช้รหัสกลางใน `data/conditions.json` (เช่น `liver_disease`, `diabetes`, `peptic_ulcer`, `gallstones`)

## ลำดับความรุนแรง

`avoid` > `caution` > `info` ผลลัพธ์เรียงตามความรุนแรง แล้วตามชั้นหลักฐาน (A ก่อน C)

---

## R1: ข้อห้ามตามเงื่อนไขผู้ใช้

**เงื่อนไข:** สำหรับแต่ละสมุนไพรที่เลือก ตรวจ `contraindications`, `age_limits`, `condition_cautions` เทียบกับ `profile`

**ผลลัพธ์:** flag ระดับตามที่เล่มระบุ ไม่ปรับเพิ่ม/ลดเอง

**จุดที่ต้องระวัง**
- `context` ของข้อห้าม (เช่น ขิง "ไม่แนะนำบรรเทาคลื่นไส้ในสตรีมีครรภ์") ต้องแสดงในข้อความ ห้ามขยายเป็น "ห้ามใช้ขิงในสตรีมีครรภ์ทุกกรณี"
- ถ้า `profile` ไม่ได้กรอกเงื่อนไขหนึ่ง ให้แสดงว่า "ไม่ได้ตรวจเงื่อนไขนี้" ไม่ใช่ผ่าน

### R1 ของ "ตำรับ" (เพิ่ม 2026-10-09 ทีมอนุมัติให้ทำเท่าที่ทำได้ ร่าง รอผู้เชี่ยวชาญ)

ตำรับยาบำรุงโลหิต (`data/formula_guidelines.json`) เข้ามาเป็นรายการชนิด "ตำรับ" ที่ผู้ใช้เลือกเอง `engine/formulas.py` แปลงข้อห้าม/ข้อควรระวังของตำรับเป็นรูปแบบเดียวกับแถวสมุนไพร แล้ว R1 เดิมตัดสิน (ไม่มีกฎใหม่ ไม่มี LLM ตัดสิน)
- ข้อห้าม (avoid): "ห้ามใช้ตำรับที่มีตัวยารสร้อนในสตรีระหว่างตั้งครรภ์" (`pregnancy`) และ "ในผู้ป่วยที่มีไข้" (`fever`), "ห้ามใช้ในผู้ที่มีประวัติแพ้ตัวยาที่เป็นส่วนประกอบในตำรับ" (`allergy_to_ingredient`) ข้อควรระวัง (caution): แพ้ละอองเกสรดอกไม้ (`pollen_allergy`) หน้าพิมพ์ 4 (PDF 5)
- ข้อความธงและการ์ดหลักฐานอ้างเอกสารต้นทางของตำรับ (`source_doc_th`) ไม่ใช่เล่ม TTM first
- **ห้ามนำข้อห้ามของตำรับไปใช้กับสมุนไพรเดี่ยว** แม้ขิง กระชาย ไพล จะถูกจัดเป็นรสร้อนในเอกสารตำรับ (golden G24, `test_formula_rules_never_apply_to_single_herbs`) ตำรับไม่นับเป็นสมุนไพรในป้ายขอบเขต (`herbs_in_db`)
- ข้อสมมติที่ผู้เชี่ยวชาญต้องยืนยัน: ตำรับยาบำรุงโลหิตตามแนวทางมีกลุ่มตัวยารสร้อนเป็นส่วนประกอบที่จำเป็น (หน้าพิมพ์ 3) จึงเตือนตามข้อห้ามของตำรับเมื่อผู้ใช้เลือกตำรับนี้

## R2: สมุนไพร × กลุ่มยา

**เงื่อนไข:** แปลง `drugs` เป็นกลุ่มยาผ่าน `drug_class_map.json` แล้วจับคู่กับ `drug_cautions` ของสมุนไพร

- **ชั้น A:** มี `drug_cautions` ที่ตรงกลุ่มยาในเล่ม → flag `evidence_tier: "A"` ระดับตามเล่ม
- **ชั้น C:** สมุนไพรอยู่ใน `effect_groups` ที่ `interacts_with_drug_class` ตรงกับกลุ่มยาของผู้ใช้ และไม่มีชั้น A ของคู่เดียวกัน → flag `evidence_tier: "C"` ระดับสูงสุด `caution` ข้อความต้องระบุว่า "เป็นการอนุมานของทีม จากสรรพคุณที่เล่มระบุ"
- ถ้ามีทั้ง A และ C ของคู่เดียวกัน แสดงเฉพาะ A

**ห้าม:** ใช้ความรู้ภายนอกเพิ่มคู่ปฏิกิริยา (ชั้น B ยังไม่อยู่ใน MVP) ถ้าผู้ใช้ใส่ยาที่ไม่มีในตาราง → `unknown_inputs`

**ค่าเริ่มต้นสำหรับยาช่วงปลอดภัยแคบ:** ถ้ากลุ่มยาคือ `anticoagulant` ให้ตั้ง `pharmacist_review_required: true` ในผลตรวจ

## R3: รวมภาระความเสี่ยงตาม mechanism tag (จุดต่าง)

**เป้าหมาย:** แทนที่จะแสดงธงแยกใบ ให้สรุปว่ามีกี่แหล่งที่ผลักไปทางความเสี่ยงเดียวกัน

**วิธี:**
1. รวบรวมธงทั้งหมดจาก R1, R2, R4 ที่มี `mechanism_tag`
2. จัดกลุ่มตาม tag; นับแหล่งไม่ซ้ำ (สมุนไพรแต่ละตัว + ยาแต่ละกลุ่ม)
3. ถ้านับ >= `config.aggregate_threshold.value` → สร้าง `aggregates[]` เช่น `{"mechanism_tag": "bleeding_risk", "sources": ["khing", "garlic", "anticoagulant"], "count": 3, "severity": ระดับสูงสุดของธงในกลุ่ม}`

**ข้อควรระวัง:** ค่า threshold และการตั้งชื่อ tag เป็นการตัดสินใจของทีม ไม่ใช่ค่าทางคลินิก ผลลัพธ์ต้องติดข้อความ "สรุปรวมโดยระบบ จากธงที่มีแหล่งอ้างอิงแต่ละใบ" ห้ามให้คะแนนตัวเลขที่สื่อว่าเป็นความน่าจะเป็น

## R4: ระยะเวลา/ขนาดเกินกำหนด

**เงื่อนไข:** ถ้า `herbs[].days_in_use` > `duration_limits.max_days` ของสมุนไพรนั้น → flag

**กรณีกลุ่ม:** สมุนไพรที่เล่มระบุเป็นกลุ่มเดียวกัน (เช่น ยาระบายสกุล Senna: ขี้เหล็ก ชุมเห็ดเทศ) ให้ใช้ข้อจำกัดร่วมกัน ระบุใน `duration_limits[].group` และตรวจจากจำนวนวันที่ใช้กลุ่มนั้นต่อเนื่อง

**ตัวอย่างจากเล่ม (ต้องตรวจเลขหน้า):** รางจืดไม่ควรใช้ติดต่อเกิน 3-5 วัน; ยาระบายกลุ่ม Senna ไม่ควรใช้ติดต่อเกิน 7 วัน

**ขนาด:** ใช้เฉพาะเมื่อเล่มระบุเพดานชัดเจน ถ้าเล่มระบุเพียงขนาดที่ใช้ทั่วไป ให้แสดงเป็น `info` ไม่ใช่ธงเกินขนาด

## R5: red flag อาการ

**เงื่อนไข:** ถ้า `symptoms` ตรงกับอาการในส่วนอาการของเล่มที่มีรายการ "สัญญาณที่ควรไปพบแพทย์" → แสดงรายการนั้นเป็น `info`/`caution` พร้อมเลขหน้า ข้อมูลต้องสกัดจากส่วนอาการของเล่ม (ยังไม่ได้ดึง) และตรวจ 100%

## R6: Safe-swap

**เป้าหมาย:** เมื่อมีธง `avoid`/`caution` ที่ผู้ใช้ควรเลี่ยง เสนอสมุนไพรอื่นในเล่มที่ใช้กับอาการเดียวกัน (`symptom_id` ตรงกัน) และไม่ติดธงสำหรับผู้ใช้คนนี้

**วิธี (constraint solving ง่าย ๆ):**
1. ตัวเลือก = สมุนไพรทั้งหมดที่มี `uses[].symptom_id` = อาการที่ผู้ใช้ระบุ
2. กรองทิ้งตัวที่ติดธง `avoid` หรือ `caution` จาก R1, R2, R4 สำหรับ profile/ยาของผู้ใช้
3. จัดอันดับ: ไม่ติดธงเลย > ติดธง `info` เท่านั้น; แล้วตามจำนวนธงน้อย; ผลเสมอกันให้เรียงตามชื่อ (เพื่อให้ทำซ้ำได้)
4. แสดงสูงสุด 3 ตัวเลือก พร้อมวิธีใช้/ขนาดจากเล่มและเลขหน้า

**ข้อความที่ต้องแสดง:** "เป็นรายการจากหนังสือแนวทางฯ ที่ไม่พบธงในฐานข้อมูลนี้สำหรับข้อมูลที่คุณกรอก ไม่ใช่ข้อแนะนำทางคลินิก โปรดปรึกษาเภสัชกร" ห้ามใช้คำว่า "ปลอดภัยกว่า" โดยไม่มีเงื่อนไข ถ้าไม่มีตัวเลือก ให้แสดง "ไม่พบทางเลือกในฐานข้อมูล"

**ข้อจำกัด:** ความถูกต้องขึ้นกับข้อมูลอาการ→สมุนไพรที่ดึงจากเล่ม (ยังไม่ได้ตรวจครบ) และ "ไม่ติดธง" หมายถึงไม่พบในฐาน ไม่ใช่ไม่มีความเสี่ยง

## ใบสรุปเภสัชกร (output ประกอบ)

ประกอบจากผลตรวจ ไม่ใช้ LLM ตัดสิน:
- รายการยา (ตามที่ผู้ใช้กรอก) และสมุนไพรที่เลือก
- ธงเรียงตามความรุนแรง พร้อมชั้นหลักฐาน เลขหน้า และสถานะ `verified`
- `aggregates`
- `coverage.unknown_inputs`
- คำถามที่ควรถามต่อ: ขนาดและความถี่, ระยะเวลาที่ใช้, ผลตรวจติดตาม (เช่น ค่าการแข็งตัวของเลือดหากใช้ยากันเลือดเป็นลิ่ม **[ผู้เชี่ยวชาญต้องตรวจรายการคำถาม]**), อาการผิดปกติที่เกิดขึ้น

## การเรียบเรียงภาษาด้วย LLM (/explain)

- Input: JSON ผลตรวจเท่านั้น (ไม่ส่งข้อความดิบของผู้ใช้)
- Output: JSON `{"summary_th": "...", "items": [{"flag_id": "f1", "text_th": "..."}]}`
- Post-check: ตรวจว่าข้อความไม่มีชื่อสมุนไพร/ยา/ตัวเลขที่ไม่อยู่ใน JSON; ถ้าตก ใช้ template จาก `message_th` ของแต่ละธง
- บังคับต่อท้ายด้วย `disclaimer_th` เสมอ

## ข้อกำหนดการทดสอบ

- ทุกกฎมีเคสเตือน 1 เคสและไม่เตือน 1 เคสขั้นต่ำ
- ชุด golden: `docs/golden_cases.json` ทุกเคสต้องผ่านก่อน merge หรือมีบันทึกเหตุผล
- เคสขอบ: ยาที่ไม่อยู่ในตาราง, สมุนไพรที่ไม่อยู่ในฐาน, ผู้ใช้ไม่กรอกข้อมูล, สมุนไพรซ้ำ, ยาหลายตัว
- เคสความสม่ำเสมอ: เรียกซ้ำ 2 ครั้งต้องได้ผลเหมือนกัน
