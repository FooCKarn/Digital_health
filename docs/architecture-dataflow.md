# Logic, Data Flow และบทบาทของ AI (HerbGuard TTM)

เอกสารนี้อธิบายตามเกณฑ์ผู้จัดข้อ 2-3 ของ `hackathon.md` เขียนจากสิ่งที่ **ทำงานแล้วใน repo** (สถานะข้อมูล: ยังไม่ผ่านการตรวจโดยผู้เชี่ยวชาญ ทุกแถว `verified:false`)

## 1. ภาพรวม Input → Process → Output

```
ผู้ใช้ (เลือกจากรายการ หรือพิมพ์ข้อความอิสระ)
   │  [AI จุด 1 เฉพาะกรณีพิมพ์ข้อความ: เสนอรายการ -> ผู้ใช้ตรวจแก้และยืนยัน]
   ▼
INPUT (JSON): สมุนไพร+ส่วนที่ใช้+จำนวนวัน, ยา, โปรไฟล์ (อายุ/ตั้งครรภ์/ให้นม/โรค)
   │  engine/service.py ตรวจชนิด ช่วงค่า ความยาว รหัสโรค (ไม่ผ่าน -> 400)
   ▼
PROCESS (engine/check.py ฟังก์ชันล้วน ไม่มี AI ไม่มี side effect ผลทำซ้ำได้)
   R1 ข้อห้ามตามเงื่อนไขผู้ใช้ │ R2 สมุนไพร x กลุ่มยา (ชั้น A) │ R4 ระยะเวลาเกินกำหนด
   R3 รวมภาระความเสี่ยงตาม mechanism_tag (นับแหล่งไม่ซ้ำ ไม่มีคะแนน)
   ข้อมูล: data/herbs.json (จากหนังสือ TTM first พร้อมเลขหน้า) + data/drug_class_map.json
           + data/config.json (พารามิเตอร์ที่ทีมตั้งเอง ติดป้าย) + data/mechanism_tags.json
   ▼
OUTPUT (JSON): flags[] (rule_id, severity, evidence_tier, source_page, verified, message_th)
               aggregates[], coverage{herbs_in_db, unknown_inputs, not_checked}, disclaimer_th
   │
   ├─► หน้าผลตรวจ + ใบสรุปเภสัชกร (ประกอบด้วยโค้ด engine/summary.py)
   └─► [AI จุด 2 เมื่อผู้ใช้กดปุ่ม: เรียบเรียงภาษาง่ายจาก JSON ผลตรวจ -> ผ่านตัวตรวจ -> ไม่ผ่านใช้ template]
```

Endpoint (Vercel, Python stdlib): `GET /api/meta`, `POST /api/analyze`, `POST /api/parse`, `POST /api/explain`, `POST /api/feedback`, `POST /api/ask` (แชต) หน้าเว็บ: `public/index.html`

## 2. ที่มาของข้อมูล (ไม่ใช้ความจำของโมเดล)

1. `scripts/extract_pdf.py` ดึงข้อความจาก PDF (ล้างอักขระซ้ำ แยก 50 รายการ จับคู่หน้าพิมพ์ = หน้า PDF − 8)
2. `scripts/round_a.py` ตัดหัวข้อ (ข้อห้ามใช้/คำเตือน/ข้อควรระวัง) ด้วย regex
3. รอบ B: สรุปความเป็นรายการโครงสร้าง พร้อม `evidence_quote` (วลีสั้นจากต้นฉบับ)
4. `scripts/verify_extraction.py`: **ปัดตกทั้งชุดถ้ามี evidence_quote ใดไม่พบในต้นฉบับ** และคำนวณเลขหน้าจากตำแหน่งที่พบ (โมเดลไม่ได้กรอกเลขหน้า)
5. **คนตรวจกับต้นฉบับแล้วตั้ง `verified:true`** (ขั้นนี้ยังไม่ได้ทำ จึงทุกแถวเป็น `verified:false` และ UI แสดงคำว่า "ยังไม่ผ่านการตรวจโดยผู้เชี่ยวชาญ")

## 3. AI ทำหน้าที่อะไร อยู่ตรงไหน (3 จุดเท่านั้น)

| | จุดที่ 1: แปลงข้อความอิสระ | จุดที่ 2: เรียบเรียงคำอธิบาย |
|---|---|---|
| ข้อมูลเข้า | ข้อความที่ผู้ใช้พิมพ์ + รายชื่อสมุนไพรในฐาน | JSON ผลตรวจที่ **engine คำนวณใหม่ฝั่งเซิร์ฟเวอร์** (ไม่ส่งข้อความดิบของผู้ใช้) |
| AI ทำอะไร | เสนอรายการสมุนไพร (id จากฐานเท่านั้น) และยา | เรียบเรียงข้อความภาษาง่ายต่อธงแต่ละใบ |
| ตัวตรวจ (โค้ด ไม่ใช่ AI) | id ที่ไม่อยู่ในฐานไม่ถูกเดา (นับเป็น `dropped` แจ้งผู้ใช้); **ทุกสตริงที่ AI ส่งกลับ (ชื่อยา/unmatched) ต้องมาจากข้อความผู้ใช้จริง สั้น ไม่เกิน 100 ตัวอักษร และไม่มีสิ่งแปลกปลอม**; จำนวนวันต้อง 1-365; จำกัดจำนวนรายการ | schema ครบทุก `flag_id`; ตัวเลขต้องอยู่ใน JSON; ชื่อสมุนไพร/ยานอกผลตรวจ = ตก; **คำภาษาอังกฤษทุกคำต้องมีใน JSON (กันชื่อยาที่แต่งขึ้นแม้ไม่อยู่ในฐาน)**; **คำต้องห้าม (ปลอบใจ/ชี้นำ) จาก `data/config.json`**; **อักขระนอกชุดไทย/ASCII (จีน อีโมจิ อักขระล่องหน), URL/HTML/markdown/โค้ด, ข้อความยาวผิดปกติ = ตก**; ตรวจการกลับความหมายแบบหยาบ (ข้อความที่มี "ไม่/ห้าม" ต้องยังมีคำปฏิเสธ) |
| ถ้าไม่ผ่าน/ใช้ AI ไม่ได้ | แจ้งผู้ใช้ให้กรอกเอง | ใช้ `message_th` ของธง (template) และบอกที่มาในหน้าจอ |
| ผลไปใช้ต่อ | **ผู้ใช้ต้องยืนยัน** ก่อนส่งเข้า engine | แสดงเป็นข้อความเสริม ไม่เปลี่ยนธง ไม่เพิ่มข้อเท็จจริง |

### จุดที่ 3: แชต "ถามต่อจากผลตรวจ" (RAG แบบคุมได้)

ไหล: `POST /api/ask` (เซิร์ฟเวอร์คำนวณผลตรวจใหม่จากรายการที่ส่งมา) -> ตัวแยกประเภทคำถามแบบกฎ (ฉุกเฉิน/ขนาดยา/วินิจฉัย/ถาม "ปลอดภัยไหม" -> ข้อความตายตัว ไม่เรียก AI) -> ด่าน "หลักของคำถาม" -> ค้นรายการข้อมูล -> ตอบแบบสกัดข้อความ (ค่าเริ่มต้น) หรือ AI เรียบเรียง (เฉพาะเมื่อตั้ง `HERBGUARD_CHAT_LLM=1`) -> ตัวตรวจ -> ผลลัพธ์พร้อมรหัสรายการ/เลขหน้า

- **ค้นก่อนเสมอ:** ค้นจากรายการข้อมูล 108 รายการของเรา (ไม่ใช่ข้อความเต็มของหนังสือ) ด้วยดัชนี n-gram ตัวอักษรถ่วงน้ำหนัก idf ภายในขอบเขตสมุนไพรของผลตรวจ ผลซ้ำได้เสมอ ชื่อสมุนไพรใช้กำหนดขอบเขตเท่านั้น ไม่นับเป็นคะแนนความเกี่ยวข้อง เกณฑ์ขั้นต่ำ `rag_min_score` (0.15) อยู่ใน `data/config.json`
- **ด่านหลักของคำถาม (anchor gate):** ค้นได้ก็ต่อเมื่อคำถามเอ่ยถึงยา/กลุ่มยา โรค/ภาวะ หรือคำบอกหัวข้อ (`rag_kind_keywords`, `rag_synonyms` ใน config) ไม่เช่นนั้นปฏิเสธด้วยข้อความตายตัว เพราะคะแนนอย่างเดียวแยกคำถามนอกเรื่องออกไม่ได้
- **ตอบแบบสกัดข้อความเป็นค่าเริ่มต้น** (ไม่ต้องมี AI) **AI เรียบเรียงเป็นแบบเลือกเปิด:** ใช้เฉพาะเมื่อตั้งตัวแปรสภาพแวดล้อม `HERBGUARD_CHAT_LLM=1` (ไม่ตั้ง = ไม่เรียก AI แม้มี `GEMINI_API_KEY`) เพราะตัวตรวจการกลับความหมายยังเป็น heuristic ระดับคำ เมื่อเปิด AI เรียบเรียงจากรายการที่ค้นได้เท่านั้น ต้องอ้างรหัส **ครบทุกรายการที่ค้นได้** (กันการตัดคำเตือนทิ้ง) ผ่านตัวตรวจชุดเดียวกับจุดที่ 2 (อักขระ/URL/ความยาว/คำต้องห้าม/ตัวเลขและคำอังกฤษต้องอยู่ในรายการที่ค้นได้/ชื่อสมุนไพรและยานอกรายการ/การกลับความหมาย รวมรูป "ไม่มี/ไม่ต้อง + ข้อห้าม/หลีกเลี่ยง") ไม่ผ่านกลับไปแบบสกัด
- **ถาม "ใช้ได้ไหม/ทำไมถึงเตือน" เรื่องที่ไม่ได้กรอก:** ถ้าคำถามเอ่ยถึงสมุนไพรที่ไม่ได้ตรวจ หรือยา/โรคที่ไม่มีธงใดครอบคลุม ระบบไม่ตอบ "ไม่พบธง" แต่แสดงธงปัจจุบัน (ถ้ามี) และรายการในฐานข้อมูลที่เกี่ยวข้องแบบสกัดข้อความ พร้อมข้อความตายตัวให้เพิ่มลงแบบฟอร์มแล้วกดตรวจ (ไม่ใช้ AI ในทางนี้)
- **ไม่เรียก AI** (แม้เปิด `HERBGUARD_CHAT_LLM=1`) เมื่อเป็นอาการฉุกเฉิน, ถาม "ปลอดภัย/ใช้ได้ไหม", ขอขนาดยา, ขอวินิจฉัย, คำถามนอกฐาน (ข้อความตายตัวจาก `data/config.json` ที่ทีมตั้ง ผู้เชี่ยวชาญต้องตรวจ) และ **ใช้ได้โดยไม่ต้องมี LLM** (ไม่ตอบ 503)
- **ไม่ส่งประวัติแชตให้ AI** (ส่งแค่คำถามล่าสุด + รายการที่ค้นได้) ข้อความแชตเก็บใน `sessionStorage` ของแท็บผู้ใช้เท่านั้น (ข้อมูลโปรไฟล์ที่กรอกอยู่ในหน่วยความจำของหน้า ไม่ลง storage) เซิร์ฟเวอร์ไม่เก็บและไม่บันทึกคำถาม
- **ข้อความจากฐานข้อมูลแสดงตามต้นฉบับ:** ข้อความข้อมูลที่ค้นได้ถูกแสดงตรง ๆ จึงอาจมีคำว่า "ปลอดภัย" ตามที่อยู่ในข้อมูล (2 จุดใน `data/herbs.json` รอทีมพิจารณาเทียบกฎข้อ 5)
- **ข้อจำกัด:** การค้นแบบตัวอักษรอาจพลาดคำถามที่ใช้คำต่างจากข้อมูล (ระบบปฏิเสธแทนการเดา) สมุนไพรนอกฐานผสมยาที่รู้จักอาจได้ข้อมูลของยาเป็นคำตอบ (K01 บันทึกเป็น known_limit ในชุดประเมิน) ยังไม่ได้ทดสอบกับ LLM จริง เบราว์เซอร์จริง และโปรแกรมอ่านหน้าจอจริง

**AI ไม่ทำ:** ตัดสินว่ามีธงหรือไม่, ระดับความรุนแรง, ชั้นหลักฐาน, เลขหน้า, ความรู้ทางเภสัชวิทยาที่ไม่อยู่ในเล่ม สิ่งเหล่านี้มาจากโค้ดและข้อมูลที่ตรวจเทียบเล่มเท่านั้น

## 4. ข้อจำกัดที่ต้องบอกตรง ๆ

- ฐานข้อมูลตอนนี้ **21 จาก 50 ชนิด** และกลุ่มยาจำกัด (ตารางชื่อยา→กลุ่มยายังไม่ผ่านเภสัชกร) "ไม่พบธง" **ไม่ได้แปลว่าปลอดภัย** UI แสดงขอบเขตและ `unknown_inputs`/`not_checked` ทุกครั้ง
- ยังไม่มีผู้เชี่ยวชาญตรวจข้อมูล และยังไม่ได้วัดความแม่นยำการสกัดเทียบ golden set สกัดมือ
- ตัวตรวจความหมายของ AI จุดที่ 2 เป็นแบบหยาบ จึงให้ template เป็นทางสำรองเสมอ และยังไม่ได้ทดสอบกับ LLM จริง
- พารามิเตอร์ที่ทีมตั้งเอง (เกณฑ์ R3, อายุ "เด็ก" 7 ปี, จุดตัดช่วงวัน) อยู่ใน `data/config.json` พร้อมป้าย ไม่ใช่ตัวเลขจากเล่ม
- เครื่องมือสนับสนุนการตัดสินใจ ไม่ใช่การวินิจฉัยหรือสั่งยา ใช้ข้อมูลสมมติเท่านั้น
